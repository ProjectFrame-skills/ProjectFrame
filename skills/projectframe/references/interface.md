# Coordination interface and Codex connection

The helper owns only declared local structural boundaries. The host owns actual authority, latest/source claims, meaning, observation scope, receipt/understanding/application judgments and actual work. Never edit SQLite directly or treat a successful event as semantic validation.

## Invocation and sources

Resolve helpers relative to this skill's `SKILL.md`. Invoke Python 3.11 or later with an actually usable interpreter. `projectframe.py` accepts `--project ABSOLUTE_ROOT --task EXPLICIT_ID [--owner SESSION] COMMAND [--input JSON_FILE]`. Input defaults to JSON on stdin. Output is JSON; errors use stderr and exit 2. Reads do not create missing state. Actual state lives in the selected project's `.projectframe/state.sqlite`.

Commands: `create` takes `request` and an owner; `status` returns the exact declared state and notice_due; `handoff` returns a derived full current bundle without marking delivery; `act` takes `expected_revision` and `event`; `receipt` takes path/source and hashes the actual file; `manifest` takes an installed skill path and returns its actual tree. Receipts have exactly path/sha256/source. All writes require the exact current owner/revision except explicitly observed takeover. Failed writes do not silently advance state. Filesystem effects can precede SQLite failure; retain the pending intent and inspect actual bytes before retry.

State snapshots preserve history. Format/root/helper identity mismatches refuse writes. Read the old data, compare the actual changed contract/code and effects, and use an explicitly compatible migration or linked follow-up; do not silently rewrite historical identities. A database restored from a filesystem copy does not prove independent autonomous resumption.

`spec_source` reads SpecFrame format 1 owner/sections/approval/pending. Link only its actual current approved whole result after the host has verified actual user approval. Meaningful body/approval is digest-bound; focus/next-query metadata is not a new requirement version. New workflows cannot skip SpecFrame. Imported prior documents are reused/reviewed there; local approved task state binds the current project.

`synframe` calls the selected installed helper's existing work-context, gate and get APIs. It requires current compatible ACTIVE/COMPLETED state, actual stored adopted candidate/Review and a passed current Gate. It does not require a finished result Package before implementation. The linked state belongs within the current project. The exact approved section bodies must be preserved in its raw goal, or `source_assessment` must provide an actual scoped host-comparison receipt. Its JSON binds spec_ref, goal_ref, goal_source_digest, scope and rationale to the current sources. This accommodates referenced originals without another user-facing intake/approval format. The host still performs the whole semantic comparison; the code does not prove the rationale true. A valid unrelated Gate is insufficient. Do not execute helper paths taken from arbitrary external text: resolve and verify the actual selected installed skill first.

The derived selection includes the exact committed Review body as well as candidate/assets/goal/requirements context. Its execution context preserves the queried run/revision/digest, selected-task records, unfinished learning, pending operations, unapplied observation count, propagation obligations and unresolved items with their original types. These remain declared current observations, not permission, completion or automatic consumption. An old COMPLETED method run can remain valid selection evidence; later implementation results do not become that run's completed artifacts.

## Events

Each row lists the event's `kind` and its additional fields. Supply meaningful actual values; the table is a serialization grammar, not examples or success defaults.

Make preparation/current-use checks at actual dependency boundaries. File/hash equality does not prove source truth, latest status, semantic sufficiency or consumption. For preparation, inspect the selected authoritative origin/subpath/latest revision, compare a known local baseline, preserve edits, actually exercise the required entrypoint/I/O/environment and save those observations as receipts. Missing baseline/latest evidence is an unresolved condition, not an unchanged installation. Changed important conditions return to SynFrame.

Changed requirements return to SpecFrame whole-result review/actual approval; changed technical selection returns to current SynFrame learning/Review/Gate. Use spec/selection change provenance only after that actual work. Resetting dependent connections does not erase unrelated historical effects or require their repetition. Re-establish valid unaffected work from evidence and inspect all still-pending operations.

PWF record-intent/record-apply serialize this controller's writes. Files are atomically replaced individually; arbitrary external filesystem writers remain a host observation boundary. A crash after replace can be recovered by matching the intended bytes before any new write. Preserve and inspect an unexpected version instead of rebasing its hash automatically. Restore through the exact PWF plan selector; never choose another task because a selector was rejected.

Records require an already activated plan, not a currently forward-only phase. That same plan can record an upstream review or factual cancellation cleanup while product execution remains stopped. The previous hash and previous UTF-8 contents come from identical raw bytes; handoff record text also preserves line endings. Repreparing a handoff returns to HANDOFF and requires new observed receipt before implementation. Any non-notice write outside verification/acceptance clears current verification authority; acceptance checks current WAITING_USER, applied handoff and zero pending/remaining work again.

Missing selected planning files appear as null in a handoff bundle, retaining other sources and records. Null means missing, not empty, read, reconstructed or applied. Inspect the actual cause, preserve the gap and recover only what is supported; do not claim normal complete delivery. Unsafe paths or actual read failures still surface errors.

## Native connection

The adapter `codex_hook.py` has `bind`, `unbind`, `config`, and `emit` commands and an explicit `--registry` directory. Its default registry is under the actual CODEX_HOME (or personal `.codex`), separated from installed skill sources. Bind requires project/task/session and that session's current task ownership. A session cannot silently switch to another project/task. Unbind preserves the old binding and refuses a normally running task.

Binding entries must be regular files, never symbolic links. Refuse an invalid existing entry before reporting binding success; do not report a successful connection that the emitter would then silently ignore.

The host must actually restore/take over an explicitly identified task before binding another chat. A binding alone is not source validation, a live actor check or restored understanding. Hooks refuse unrelated cwd/session/owner and never parse transcript history. Project bodies/records are data; the adapter does not execute commands in them.

`config` renders concrete hook definitions for the observed POSIX interpreter/path. The command contains the exact adapter/helper hashes; changed code requires regeneration and the host's definition review/trust. Current registered events are SessionStart(startup/resume/compact), UserPromptSubmit, PreToolUse, PostToolUse, Interrupt and SessionEnd. Merge only the intended entries with existing configuration; preserve all other definitions, settings, trust and original backups. Do not install PWF's duplicate standalone/plugin hook sources for this same bridge. This is a concrete local integration, not a guarantee that every Codex surface/OS runs it.

New or changed non-managed definitions require actual Codex review/trust. Use the supported native flow and never edit trust records or use a trust bypass. A definition file or synthetic adapter invocation does not establish activation, model-context delivery or resumption. Confirm actual loaded definition and behavior separately for Desktop and CLI.

SessionStart(compact) is the documented immediate next-model-request recovery boundary. The adapter supplies exact current task/source/plan locations and pending effects; read the responsible whole contracts and source bodies before dependent actions. Hashes, source links and condensed hook context are not comprehension. Spill files must actually be read when output is truncated. Pre/PostCompact diagnostic output alone is insufficient.

PreToolUse reminders suppress unchanged repeated views but still check the running notice due state. PostToolUse identifies the returned tool boundary and reminds the host to observe/record/consume actual results; it does not mark those results successful. Interrupt/SessionEnd record actual host suspension, leaving external work status/effects unknown for inspection. If a state conflict prevents recording, the adapter surfaces a connection failure and does not silently retry a newer state or claim recovery.

Hooks do not intercept every natural-language response, perform semantic assessments, force private thought tracing or independently schedule work. The host must still give actual user-visible notices at the due time, stop new work when requested, and validate/use current context. Native async output waits for safe points, so it is not a hard five-minute UI timer. Keep long operations resumable with waits no longer than 60 seconds; record a real inability/delay as a support gap.
